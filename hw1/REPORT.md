# Отчёт по HW1

## 1. Регулярные выражения токенов

Алфавит — ASCII (коды 0..127). Приоритет — порядок в таблице (меньше номер — выше приоритет).

| # | Токен | Вид | Regex |
|---|---|---|---|
| 0–8 | `KW_FUNCTION`, `KW_RETURNS`, `KW_WHILE`, `KW_IF`, `KW_ELSE`, `KW_ASSERT`, `KW_ASSUME`, `KW_INVARIANT`, `KW_LENGTH` | token | `function`, `returns`, `while`, `if`, `else`, `assert`, `assume`, `invariant`, `length` |
| 9 | `IDENT` | token | `[A-Za-z_][A-Za-z0-9_]` |
| 10 | `INT` | token | `0\|[1-9][0-9]` |
| 11 | `BAD_INT` | error | `0[0-9]+` |
| 12 | `WS` | skip | `[ \t\r\n]+` |
| 13 | `COMMENT` | skip | `//[^\r\n]` |
| 14–20 | `EQ NE LE GE LT GT ASSIGN` | token | `==` `!=` `<=` `>=` `<` `>` `=` |
| 21–24 | `PLUS MINUS STAR SLASH` | token | `\+` `-` `\` `/` |
| 25–32 | `LPAREN RPAREN LBRACKET RBRACKET LBRACE RBRACE COMMA SEMI` | token | `\(` `\)` `\[` `\]` `\{` `\}` `,` `;` |

Проектные решения:

 Ключевые слова vs IDENT. `function` подходит под два правила; в принимающем состоянии
  ДКА хранится правило с наименьшим приоритетом, поэтому ключевые слова стоят выше `IDENT`.
  `functionX`, `iff`, `If` — `IDENT` по максимальному мунку.
 Ведущие нули. `INT = 0|[1-9][0-9]` сам по себе разбил бы `01` на `INT(0) INT(1)`.
  Чтобы `00`/`01` были ошибкой целиком, добавлено правило-ловушка `BAD_INT = 0[0-9]+`
  вида `error`: автомат его принимает, а лексер выдаёт `ERROR "01"`.
 COMMENT не включает `\r`, поэтому в `//x\r\n` перевод строки CRLF уходит в `WS`.
 `[^...]` и `.` дополняются до ASCII, не до Unicode: non-ASCII внутри комментария — тоже ошибка
  (алфавит языка фиксирован).

## 2. Конвейер

1. regex → AST (рекурсивный спуск, `funnylex/regex.py`).
2. AST → НКА по Томпсону (`nfa.py`): по фрагменту с одним входом/выходом на каждый узел;
   `a+ = a a`, `a? = a|ε`. Объединённый НКА — новый старт с ε-дугами в НКА каждого токена,
   конечное состояние токена помечено его приоритетом.
3. Классы символов. ASCII разбивается на классы, которые не различает ни одна дуга НКА
   (уточнение разбиения). Это сжимает таблицу со 128 до 39 столбцов без потери точности;
   40-й столбец — `NON_ASCII`.
4. НКА → ДКА построением подмножеств (ε-замыкание + move по представителю класса).
   Пустое множество НКА-состояний — явное состояние-ловушка. Метка ДКА-состояния —
   минимальный приоритет среди содержащихся принимающих НКА-состояний.
5. Минимизация Хопкрофтом (`dfa.py`), O(k·n·log n). Начальное разбиение — по метке
   (`None`, `IDENT`, `INT`, …), а не просто «принимает/не принимает»: иначе склеились бы
   состояния разных токенов.
6. Перенумерация BFS от старта (старт = 0) и экспорт.

## 3. Размеры автоматов

| | Состояний | из них принимающих | ловушка |
|---|---|---|---|
| НКА (Томпсон) | 191 | 33 | — |
| ДКА после построения подмножеств | 82 | 79 | 1 |
| Минимальный ДКА (Хопкрофт) | 77 | 74 | 1 (`trap = 1`) |

Столбцов в таблице: 40 (39 классов ASCII + `NON_ASCII`).

Хопкрофт склеил 5 пар — это типичный артефакт `x+ = x x`: состояние «после первого
символа» и «после следующих» эквивалентны:

| Слито | Примеры строк |
|---|---|
| `WS` | `\t` и `\t\t` |
| `INT` | `1` и `10` |
| `IDENT` | `A` и `A0` |
| `COMMENT` | `//` и `//\x00` |
| `BAD_INT` | `00` и `000` |

Остальные состояния различимы: два непринимающих (старт и состояние после `!`), ловушка,
и принимающие состояния — по одному на каждый префикс ключевого слова (`f`, `fu`, … — они
имеют метку `IDENT`, но разные продолжения).

## 4. Ловушка

 Состояние `1` (`"trap": true` в JSON, `TRAP` в CSV): все переходы ведут в себя, не принимает.
 Столбец `NON_ASCII`: из любого состояния ведёт в ловушку — так обрабатывается выход за
  алфавит (`é`, `ж`, `😀`, NBSP и т.д.).
 45 ASCII-символов не начинают ни одного токена и из старта сразу ведут в ловушку (класс 0,
  помечен `UNCOVERED:` в именах классов):
  `\x00-\x08 \x0B \x0C \x0E-\x1F " # $ % & ' . : ? @ \ ^ ` | ~ \x7F`.
  Символ `!` в этот список не входит (он префикс `!=`), но одиночный `!` не принимается.
 Лексер прекращает поиск сразу при входе в ловушку. Если ни один префикс не принят — выдаётся
  `ERROR` из одного символа и разбор продолжается со следующего.

## 5. Тестирование

Все тесты лежат в одном файле `tests/cases.json`, по строке на тест — входная строка и ожидаемый результат:

```json
{"input": "01", "expect": "BAD_INT"}
{"input": "01+1", "tokens": [["ERROR", "01"], ["PLUS", "+"], ["INT", "1"]]}
{"code": 64, "char": "@", "expect": "ERROR", "trap": true}
```

 match — вся строка через ДКА: ожидаемый токен или `null`, и попала ли строка в ловушку;
 lex — разбиение лексером: ожидаемый список `[тип, лексема]`;
 chars — один символ: проверяются и match, и lex.

| Тема | Тестов | Что покрыто |
|---|---|---|
| пробелы | 17 | пустая строка; пробел, Tab, `\r`, `\n`, CRLF и их смеси; `\v`, `\f` — не пробелы |
| числа | 26 | `0`, `7`, `10`, длинные числа; `00`, `01`, `007`, `0123` → ошибка целиком; `0x`, `12abc`, `1.5`, `-1` |
| идентификаторы | 21 | `_`, `__init__`, `_1`, `x_`, разные регистры; `1x`, `a$b` — не идентификаторы |
| ключевые слова | 59 | все 9 ключевых слов; для каждого суффикс `_`/цифра, обрезанный префикс, другой регистр → IDENT |
| операторы | 36 | все 19 операторов и разделителей; `===`, `<==`, `!==`, `=<`, `<>`, `>>=`; одиночный `!` |
| комментарии | 16 | `//`, `///`, до `\n`/CRLF/конца файла; `/ /` и `x/y` — не комментарий |
| non-ASCII | 16 | Latin-1, кириллица, эмодзи, NBSP, `\uffff`; non-ASCII внутри имён и комментариев |
| весь алфавит (`chars`) | 136 | каждый из 128 ASCII-символов + 8 символов вне ASCII |
| программа | 1 | фрагмент программы на Funny с CRLF, ключевыми словами и ошибкой `01` |
