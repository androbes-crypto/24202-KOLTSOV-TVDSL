# Отчёт по HW3: типы и ограничения

## 1. Система типов

```
T ::= int | bool | T[] | (T1, …, Tn) -> (R1, …, Rm)
```

* `int`, `bool` — базовые типы.
* `T[]` — массив, любая размерность (`int[][]`). Массивы — значения: `a[i] = v` создаёт новый
  массив (`a = Update(a, i, v)`), поэтому присваивание массива копирует его по смыслу.
* Тип функции — только у функций; переменных-функций и функций как значений нет.
* Внутренние служебные типы: **переменная типа** (для вывода) и **тип-ошибка**
  (для подавления каскадов).
* `string` не поддерживается — в языке нет строк.

Типы сравниваются структурно и без приведений: `int ≠ bool`, `int[] ≠ int[][]`.

## 2. Как устроена проверка

1. **Сигнатуры.** Первый проход собирает все функции: имена, типы параметров и результатов.
   Поэтому функции можно вызывать до их объявления и рекурсивно.
2. **Тело каждой функции.** Стек областей видимости: уровень функции (параметры и
   результаты), затем по уровню на каждый блок и на тело `if`/`while` без фигурных скобок.
   Для понятных сообщений заранее собираются все `var` функции: так отличается
   «используется до объявления» от «не видна вне своего блока» и от «неизвестное имя».
3. **Выражения** проверяются снизу вверх; тип каждого узла записывается в AST.
4. **Аннотация.** После проверки функции типы (в том числе выведенные) переводятся в строки
   и записываются в поля `type`, `ref`, `decl`, `inferred`, `signature`.

## 3. Унификация и вывод типов локальных (бонус)

* `var x;` / `var x = e;` получают **переменную типа** α.
* Присваивание `x = e` вызывает `unify(α, тип(e))`: α связывается с типом первого
  присваивания.
* Дальше α ведёт себя как обычный тип: несовпадение при следующем присваивании — ошибка.
* Читать переменную с ещё не выведенным типом нельзя — это ошибка («используется до первого
  присваивания»). Поэтому тип определяется **только присваиваниями**, а не использованием,
  как требует задание.
* В конце функции переменная, тип которой так и не выведен, — ошибка «не удалось вывести тип».
* «Первое присваивание» — первое **по тексту программы**. В
  `if (c) x = 1; else x = true;` тип `x` — `int`, а второе присваивание — ошибка.

## 4. Подавление каскадов

Если у подвыражения ошибка, его тип — `<ошибка>`. Этот тип совместим со всем и не порождает
новых сообщений. Переменная, которой присвоено ошибочное значение, тоже получает тип
`<ошибка>`. Поэтому одна ошибка даёт одно сообщение, а проверка продолжается до конца программы.

## 5. Ограничения

* **Нет проверки определённого присваивания** (definite assignment): результат функции может
  остаться неприсвоенным, а `var x: int;` можно читать до присваивания — это работа анализа
  потока данных, а не типов.
* Вывод типов **внутри функции** и **только для локальных**; типы параметров и результатов
  обязательны.
* Перекрытие имён запрещено (в том числе параметров во вложенных блоках). Это сознательное
  решение: каждая переменная функции однозначно определяется парой `(имя, позиция объявления)`,
  что упрощает IR. Одинаковые имена в **соседних** блоках разрешены.
* Параметры можно переприсваивать, как локальные переменные.
* Нет перегрузки функций и неявных приведений типов.
* Выход за границы массива и деление на ноль — ошибки времени выполнения/верификации,
  на этапе типов не проверяются.
* При синтаксических ошибках семантическая проверка не выполняется.

## 6. Изменения в HW2

Для HW3 в парсер HW2 внесены две совместимые правки (грамматика осталась LL(1), все тесты HW2
проходят):

* `var x;` и `var x = e;` — аннотация типа у `var` стала необязательной (для бонуса);
* позиция узла `Assign` — имя переменной слева, а не знак `=` (точнее сообщения об ошибках).
