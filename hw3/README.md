# HW3. Семантические проверки и типы для Funny

Python 3.10+, без внешних библиотек. Используется **парсер и AST из HW2** (`../hw2/funny`),
который в свою очередь использует **лексер из HW1** (`../hw1/funnylex`).

## Быстрый старт

Папки `hw1`, `hw2`, `hw3` лежат рядом (как в репозитории `homeworks/`).
Если HW2 в другом месте: `export FUNNY_HW2=/путь/к/hw2`.

```bash
cd hw3
python3 -m sema check examples/inference.fun             # аннотированный AST
python3 -m sema check --symbols examples/inference.fun   # только сигнатуры и типы переменных
python3 -m sema check examples/errors.fun                # ошибки с позициями
python3 -m sema test                                     # все тесты
```

| Команда | Что делает |
|---|---|
| `python3 -m sema check FILE` | проверяет программу; печатает аннотированный AST текстовым деревом, ошибки — в stderr в формате `файл:строка:столбец: ошибка: текст`. Код возврата 1 при ошибках |
| `... --json` | аннотированный AST в JSON |
| `... --symbols` | только сигнатуры функций и типы локальных переменных (выведенные помечены) |
| `... --partial` | печатать AST и при семантических ошибках |
| `python3 -m sema test [-v] [--update]` | прогон `tests/positive.txt` и `tests/negative.txt` |
| `python3 -m unittest discover -s tests -v` | то же + проверки JSON, позиций и устойчивости |

## Пример

```
function f(x: int, a: bool[]) returns (r: int)
{
  var n = x + 1;
  var positive;
  positive = n > 0;
  var copy;
  copy = a;
  var first = copy[0];
  if (first || positive) r = n; else r = 0;
}
```

## Поддерживаемые конструкции и правила

### Типы

`int`, `bool`, массивы любой размерности (`int[]`, `bool[][]`, …) и типы функций
`(int[], int) -> (int)` — последние только у функций, значений-функций в языке нет.
Строк в Funny нет, поэтому `string` не поддерживается.

### Имена и области видимости

| Правило | Ошибка |
|---|---|
| функции видны во всей программе (можно вызывать функцию, объявленную ниже, и рекурсивно) | повторное объявление функции |
| параметры и результаты видны во всём теле | одинаковые имена параметров/результатов |
| `var` видна от объявления до конца своего блока | использование до объявления; использование вне блока |
| тело `if`/`while` без `{}` — тоже отдельная область | |
| имя нельзя объявить повторно в том же блоке и нельзя перекрыть внешнее имя | повторное объявление, перекрытие |
| в инициализации переменной её саму использовать нельзя | `var x: int = x + 1` |
| в `requires` видны только параметры; в `ensures` — параметры и результаты | результат в `requires` |
| функции и переменные — разные виды имён | вызов переменной, функция как значение |

### Типизация

| Конструкция | Правило |
|---|---|
| `+ - * / %` | `int × int → int` |
| `< <= > >=` | `int × int → bool` |
| `== !=` | оба операнда одного типа (любого), результат `bool` |
| `&& \|\|` | `bool × bool → bool` |
| `-e`, `!e` | `int → int`, `bool → bool` |
| `a[i]` | `a: T[]`, `i: int` → `T` |
| `a[i] = v` (сахар `a = Update(a, i, v)`) | `a: T[]`, `i: int`, `v: T` |
| `length(a)` | `a: T[]` → `int` |
| `f(e1, …, en)` | число аргументов = число параметров, типы совпадают; в выражении — только функция ровно с одним результатом, её тип; как оператор — любая |
| `x = e` | тип `e` равен типу `x` |
| условия `if`, `while`, `invariant`, `assert`, `assume`, `requires`, `ensures` | `bool` |
| параметры и результаты функции | тип обязателен |
| `var x: T [= e]` | `e: T` |

Неявных приведений и перегрузок нет: `int` и `bool` не смешиваются.

### Вывод типов локальных переменных (бонус)

`var x;` или `var x = e;` без типа: переменной даётся переменная типа, которая
**унифицируется с типом первого присваивания** (инициализации или первого `x = …` по тексту).

* Следующие присваивания проверяются уже против выведенного типа; противоречие — ошибка
  с указанием, откуда тип был выведен.
* Чтение переменной до первого присваивания — ошибка (тип ещё неизвестен).
* Если переменной так ничего и не присвоено — ошибка «не удалось вывести тип».
* Выводятся и массивы любой размерности: `var row = m[i]` при `m: int[][]` даёт `int[]`.

### Диагностика

* Формат: `строка:столбец: описание`, сообщения на русском, с именами и типами.
* Позиция — узел, где ошибка: имя переменной, операнд, аргумент, оператор.
* Проверка не останавливается после первой ошибки: проверяются все функции и все операторы.
  Узлы с ошибочным типом получают тип-«ошибку», который не порождает повторных сообщений
  (`r = unknown + 1` даёт одну ошибку, а не две).
* При синтаксических ошибках (из HW2) семантическая проверка не запускается.

## Формат аннотированного AST (для HW4 / проекта)

Узлы — те же, что в HW2 (см. README HW2), с дополнительными полями:

| Узел | Новые поля |
|---|---|
| любое выражение (`Int`, `Bool`, `Var`, `Binary`, `Unary`, `Index`, `Update`, `Call`, `Length`) | `type` — тип выражения строкой: `"int"`, `"bool"`, `"int[]"`, … |
| `Var` | `ref` — `"param"` / `"result"` / `"local"`; `decl` — позиция объявления `"строка:столбец"` |
| `Assign` | `ref`, `decl` — то же для переменной слева |
| `VarDecl` | `type` — итоговый тип (указанный или выведенный); `inferred` — `true`, если выведен |
| `Function` | `signature` — `"(int[], int) -> (int)"` |
| `Call` | `signature` вызываемой функции; у вызова-оператора `type` — кортеж результатов, например `"(int, int)"` |

Пара `(name, decl)` однозначно определяет переменную внутри функции: перекрытие имён
запрещено, поэтому последующим этапам (IR, оптимизации) не нужно заново строить области видимости.

API:

```python
from sema import check
ast, diagnostics, symbols = check(source)   # symbols — строки как у --symbols (None при синтаксических ошибках)
```

## Тесты

* `tests/positive.txt` — 11 программ: явные типы локальных переменных, вывод типов
  (в том числе массивов, многомерных массивов и результата вызова), вызовы, рекурсия и вызов
  функции, объявленной ниже, несколько результатов и вызов как оператор, одно имя в соседних
  блоках, `requires`/`ensures`, равенство для `int`/`bool`/массивов, условия циклов и проверок,
  переприсваивание параметра. Ожидаемый результат — сигнатуры и типы локальных переменных;
  дополнительно раннер проверяет, что **у каждого выражения в AST есть тип**.
* `tests/negative.txt` — 24 программы: неизвестное имя и функция, повторные объявления
  (в блоке, перекрытие, параметры, функции), использование до объявления и вне блока,
  собственная инициализация, несовместимые присваивания, условия не `bool`, неверные операнды,
  сравнение разных типов, ошибки с массивами и `length`, неверное число и типы аргументов,
  функции без одного результата в выражении, вызов переменной и функция как значение,
  результат в `requires`, параметры без типа, три случая вывода типов (противоречие,
  нечего выводить, чтение до присваивания), несколько ошибок в разных функциях.
  Ожидаемый результат — точные сообщения с позициями.
* `unittest` дополнительно: поля аннотированного AST в JSON, наличие позиции у каждой ошибки,
  отсутствие падений на 2000 случайно испорченных программах.
