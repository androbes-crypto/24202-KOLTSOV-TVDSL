# HW2. Парсер Funny: LL(1), рекурсивный спуск + лексер из HW1

Ветка: **LL(1), рекурсивный спуск**. Python 3.10+, без внешних библиотек.

Лексер не написан заново: парсер использует **лексер и таблицу ДКА из HW1**
(`../hw1/funnylex`). Список токенов для HW2 лежит в `tokens.spec`; при первом запуске
по нему через HW1 строится таблица `build/dfa.json`.

## Быстрый старт

Папки `hw1` и `hw2` должны лежать рядом (как в репозитории `homeworks/`).
Если HW1 лежит в другом месте — укажите путь: `export FUNNY_HW1=/путь/к/hw1`.

```bash
cd hw2
python3 -m funny parse examples/sum.fun          # AST текстовым деревом
python3 -m funny parse --json examples/sum.fun   # AST в JSON
python3 -m funny test                            # все тесты
```

| Команда | Что делает |
|---|---|
| `python3 -m funny parse FILE [--json] [--partial]` | разбирает программу; печатает AST, ошибки — в stderr с позицией `файл:строка:столбец`. Код возврата 1 при ошибках. `--partial` — печатать AST и при ошибках |
| `python3 -m funny tokens FILE` | токены в формате P02 `вид(лексема, строка, столбец)` — проверка интеграции с лексером |
| `python3 -m funny test [-v] [--update]` | тесты из `tests/positive.txt` и `tests/negative.txt` и проверка, что парсер не зацикливается на 2000 испорченных программах. `--update` перезаписывает ожидаемые результаты |
| `python3 -m funny ll1 [-v] [--table]` | считает FIRST/FOLLOW по грамматике из `grammar.txt` и проверяет LL(1); `-v` печатает FIRST/FOLLOW, `--table` — таблицу предсказаний с отметкой конфликтных клеток |
| `python3 -m funny build-lexer` | пересобрать таблицу лексера из `tokens.spec` (через HW1) |
| `python3 -m unittest discover -s tests -v` | то же, что `test`, плюс проверки API и LL(1) |

## Пример

```
function sum(a: int[], n: int) returns (s: int)
  requires n >= 0 && n <= length(a)
  ensures s >= 0
{
  var i: int = 0;
  s = 0;
  while (i < n)
    invariant 0 <= i && i <= n
  {
    s = s + a[i];
    i = i + 1;
  }
}
```

Фрагмент вывода `python3 -m funny parse examples/sum.fun`:

## Грамматика (кратко)

Полностью — в `grammar.txt`.

| Конструкция | Синтаксис |
|---|---|
| функция | `function f(x, y) returns r { ... }`, `function f(x: int) returns r: int requires e ensures e { ... }` |
| переменная | `var x: int;`, `var y: int = 5;`, `var z = 5;`, `var w;` (тип выводит HW3) |
| присваивание | `x = e;` |
| обновление массива | `a[i] = e;`, `m[i][j] = e;` |
| условие | `if (e) stmt` `[else stmt]` |
| цикл | `while (e) invariant e ... stmt` |
| проверки | `assert e;`, `assume e;` |
| вызов | `f(x, y);` и `f(x)` в выражениях, `length(a)` |
| блок | `{ stmt ... }` |

Приоритеты (от слабого к сильному): `||` < `&&` < сравнения (неассоциативны) < `+ -` < `* / %` <
унарные `- !` < `a[i]`, `f(x)`. Бинарные операторы левоассоциативны.

LL(1): левая рекурсия устранена, операторы, начинающиеся с `IDENT`, факторизованы. Единственный
конфликт — висячий `else` — разрешён в пользу ближайшего `if`. Проверка: `python3 -m funny ll1`.

## Обработка ошибок

* **Позиции.** Лексер HW1 выдаёт смещения; `funny/lexer.py` переводит их в строку и столбец
  (с 1; табуляция — один столбец). Токен для парсера — `Token(kind, lexeme, line, col, offset)`,
  как договорились в P02 (`{kind, lexeme, line, col}`). Все сообщения в формате
  `строка:столбец: текст`.
* **Лексические ошибки:** неожиданный символ, символы вне ASCII (подряд идущие — одной ошибкой),
  число с ведущим нулём (`007` — ошибка, но парсер получает число и не выдаёт лишних сообщений).
* **Синтаксические ошибки — режим паники** (P03). После первой ошибки следующие сообщения
  подавляются, пока парсер не синхронизируется: пропускает токены до `;`, `}`, `{` или начала оператора
  (`var`, `if`, `while`, `assert`, `assume`), на уровне программы — до `function`. Если ошибка в
  заголовке `if`/`while`, а дальше начинается оператор, разбор продолжается с него.
  Поэтому в одном файле находятся все независимые ошибки.
* **Без зацикливания.** Каждый цикл парсера либо потребляет токен, либо выходит; дополнительно
  стоит ограничитель шагов. Тест прогоняет 2000 случайно испорченных программ.

Примеры сообщений:

| Ситуация | Сообщение |
|---|---|
| пустой ввод | `1:1: пустая программа: ожидалась хотя бы одна функция 'function'` |
| незакрытый блок | `6:1: ожидалось '}' (блок открыт в 2:1), но файл закончился` |
| незакрытая скобка | `3:18: ожидалось ')' (скобка открыта в 3:16), но найдено ';'` |
| лишний токен | `3:9: ожидалось ';', но найдено число 2` |
| неверный оператор | `3:6: ожидалось выражение, но найдено '<'` (для `y =< x`) |
| `a < b < c` | `операторы сравнения не ассоциативны: '<' и '<' подряд, используйте скобки или '&&'` |
| `else` без `if` | `4:3: 'else' без соответствующего 'if'` |

## Формат AST (API для следующих HW)

```python
from funny import parse, dumps, to_text

ast, diagnostics = parse(source)      # Node, list[Diagnostic(line, col, message)]
print(to_text(ast))                   # текстовое дерево
data = ast.to_json()                  # dict, пригодный для json.dumps
ast.functions[0].body.stmts           # поля узла доступны как атрибуты
```

У каждого узла: `kind`, `line`, `col` (позиция первого токена конструкции, у бинарных
операций — позиция оператора) и поля:

| kind | Поля |
|---|---|
| `Program` | `functions: [Function]` |
| `Function` | `name`, `params: [Param]`, `returns: [Param]`, `requires: [expr]`, `ensures: [expr]`, `body: Block` |
| `Param` | `name`, `type` (`"int"`, `"bool"`, `"int[]"`, `"int[][]"`, ... или `null`, если тип не указан) |
| `Block` | `stmts: [stmt]` |
| `VarDecl` | `name`, `type` (или `null`, если не указан), `init: expr \| null` |
| `Assign` | `target` (имя), `value: expr`, `sugar: "array-update"` — если это было `a[i] = e` |
| `If` | `cond`, `then: stmt`, `orelse: stmt \| null` |
| `While` | `cond`, `invariants: [expr]`, `body: stmt` |
| `Assert`, `Assume` | `cond` |
| `CallStmt` | `call: Call` |
| `Binary` | `op` (`"+"`, `"&&"`, `"<="`, ...), `left`, `right` |
| `Unary` | `op` (`"-"`, `"!"`), `operand` |
| `Int` / `Bool` | `value` |
| `Var` | `name` |
| `Index` | `array`, `index` — чтение `a[i]` |
| `Update` | `array`, `index`, `value` — новый массив, равный `array`, но с `value` на месте `index` |
| `Call` | `name`, `args: [expr]` |
| `Length` | `array` |
| `Error` | узел-заглушка на месте неразобранного выражения (только при ошибках) |

**Обновление массива как сахар:** `a[i] = e` превращается в `a = Update(a, i, e)`, а
`a[i][j] = e` — в `a = Update(a, i, Update(a[i], j, e))`. Последующим этапам не нужно
отдельно обрабатывать присваивание элементу массива.

## Тесты

Два файла, в каждом тесты идут блоками: название, программа, ожидаемый результат.

```
=== незакрытая круглая скобка
function f(x: int) returns (y: int)
{
  y = (x + 1 * (2;
  y = 3;
}
--- ожидается
3:18: ожидалось ')' (скобка открыта в 3:16), но найдено ';'
```

* `tests/positive.txt` — 17 корректных программ, после `--- ожидается` эталонное AST:
  все корректные примеры из P02, P03, P04, минимальная функция, `while` с `invariant`, цепочка `if/else if/else`, висячий `else`,
  обновление одно- и двумерного массива, объявления переменных всех типов, приоритеты и
  ассоциативность, вызовы и `length`, пустые `requires/ensures`, CRLF и комментарии,
  вложенные блоки с `assert/assume`. Тест с пометкой `[crlf]` в названии прогоняется с
  переводами строк `\r\n`.
* `tests/negative.txt` — 21 программа с ошибками, после `--- ожидается` ожидаемые сообщения:
  ошибочные примеры из P02, P03, P04, пустой ввод, только комментарий, незакрытые `{` и `(`, лишние токены и лишняя `)`, неверные
  операторы (`=<`, `:=`, `===`), цепочка сравнений, пропущенная `;`, `if` без скобок, `else`
  без `if`, лексические ошибки, ошибки в заголовке функции, оператор вне функции, ошибки в
  двух функциях сразу, `assert` без выражения, функция без тела, `returns` без результата.
* Проверка на зацикливание: 2000 программ, испорченных удалением, вставкой и перестановкой
  токенов, плюс случайные наборы токенов.

## Соответствие материалам курса и отклонения

Синтаксис сверен с примерами из P02, P03, P04, и все они есть в тестах:

| Пример | Источник | Результат |
|---|---|---|
| `function f(x, y) returns r { r = x + y; // comment ... }` | P02 | разбирается |
| `function f(x:int) returns r:int { r = x + 1; }` | P03 | разбирается |
| `function f(x) returns r { r = x + 2 * 3; }` | P04 | `x + (2 * 3)` |
| `if (a) if (b) r=1; else r=2;` | P03 | `else` у внутреннего `if` |
| `function f(x) returns r { if (x) r = 1 else r = 2 }` | P03 | одна ошибка `1:40: ожидалось ';'`, восстановление на `}` |
| `function f(x returns r { r = x + ; }` | P04 | обе ошибки, без зацикливания |
| `foo @ 42` | P02 | ошибка с позицией `1:5` |

Файл `docs/funny.ru.md` при написании был недоступен; если в нём синтаксис отличается,
правятся `grammar.txt` и `funny/parser.py`.

Расширения (в примерах курса не встречаются, но им не мешают):

* несколько результатов: `returns q: int, r: int` или `returns (q: int, r: int)`; без результата — `returns ()`;
* объявление переменных `var x: int = 0;`, тип можно опустить: `var x = 0;`, `var x;` (выводится в HW3);
* типы `int`, `bool` и массивы любой размерности;
* операторы `&&`, `||`, `!`, `%`, литералы `true`/`false`;
* `invariant` после условия `while`, до тела, без `;`;
* пустые `requires`/`ensures` (означают `true`).

Не поддерживается: `==>`, `return`, глобальные переменные, символы вне ASCII (как в HW1).
